# Project map

## Meaning

This repository is the Wolfsblvt Works website: the Astro site, the Cloudflare Worker that serves it, the contact
service every Wolfsblvt site links to, and the design sources the site was built from. Its shape keeps four things
apart that change for different reasons: what visitors see (`src/`), what runs at the edge (`worker/`, `shared/`),
how the build produces assets (`scripts/`), the approved artwork (`assets/`), and editable design history (`design/`, `references/`). This map says where each lives and why; [Architecture](ARCHITECTURE.md) explains how they work
together.

## Layout

| Path | Holds | Why it is separate |
| --- | --- | --- |
| `src/pages/` | One file per address: home, contact, privacy, impressum, 404, the 503 and `robots.txt` | Astro routes by file; the page list is the site's whole address space |
| `src/sections/` | The home walk's sections in order: hero, why, who, help, hello; `projects/` holds the five project windows, each component with its own stylesheet | The walk is one page; each section is still its own piece of copy and layout, and each window its own world |
| `src/features/pile/` | The Pile: its rendering, client controller, deal and packer, the entry scenes and interactions under `entries/<id>/`, styles | A self-contained feature with its own content model, client code and tests |
| `src/features/yoru/` | Yoru, the resident: his clips, the sprite player, the world of places, the resident who chooses what to do, opt-in memory, and `client/site.ts`, the home page's host | One character with his own engine; the core is DOM-free so it is tested like any module |
| `design/yoru/` | The resident's character sheet, his animation families as specs, reference images and the packed sheets | The source of his animation; the build reads the sheets from here |
| `tools/yoru-studio/` | The sprite studio: generation through Codex, matting, cutting, registration, packing, the candidate page and the resident rehearsal | Authoring tooling, never part of the site build |
| `src/features/contact/` | The contact page's browser script, product presentation and styles | The page around the contact service, kept apart from the service itself |
| `src/content/pile/` | One Markdown file per Pile piece | Content that grows by ordinary additions, validated by `src/content.config.ts` |
| `src/components/`, `src/layouts/` | Header, footer, Walk, icon renderer, Yoru's nap on the legal pages; the shared document | Used by every page |
| `src/scripts/` | Site-wide browser behaviour: Walk, header, reveals and travel, home and room pages | Plain modules loaded by the layout and pages, no framework |
| `src/lib/` | Build-time helpers: the Walk generator, lockup ease, marks, nav, legal-operator loader | Shared by pages, scripts and tests |
| `src/styles/` | Tokens, base, header, footer, home and room styles | One stylesheet per surface; feature styles live with their feature |
| `src/data/` | The public legal-operator fixture | The only stand-in for private data; the real record arrives at build time |
| `worker/` | The site Worker (`index.ts`), the pile seed, and the contact service in `worker/contact/` | Edge code, type-checked and tested in the Workers runtime separately from the site |
| `shared/` | The contact field contract and product list; CSP construction | Imported by the site, the Worker, build scripts and tests alike |
| `scripts/` | Fonts, identity assets, `_headers`, social cards, the output and publication checks | Build steps around Astro; each one small and runnable on its own |
| `tests/` | `unit/`, `worker/` (workerd), `e2e/` (Playwright), `fixtures/` | One folder per runtime the tests need |
| `public/` | Committed social cards; everything else here is generated by the build | Served as-is at the site root |
| `design/the-walk/` | The design canvas (`project/*.dc.html`), its tools, and the site's artwork: Yoru, the avatars, the project marks and captures (`assets/borrowed-coast/`, `assets/diffdevil/`) | The source of the site's design; the build reads the artwork from here |
| `brand/bundle/works/` | Approved Works SVGs, PNGs, animations and the [gallery](../assets/works-gallery.html) | Stable, reusable brand exports that the website and other projects consume |
| `design/marks/` | Editable generator, geometry, design canvases, sponsor specimens and Wolf's selected choices | Regeneration and history, not executable website HTML/CSS |
| `brand/source/works/` | Maintained artwork, component, tokens, fonts and licence masters | Owner-authored inputs to the deterministic exporter |
| `src/components/WorksSponsor.astro`, `src/styles/sponsor.css` | The website's sponsor binding and host styling | Reuses the canonical bundle rather than duplicating its artwork |
| `references/` | The palette handoff and the collaborators' avatar sources | Design inputs kept for provenance |
| `docs/pile/` | How to write Pile pieces, how the Pile should feel, and its technical plan | The Pile's design record, kept beside the other durable docs |
| `LICENSES/` | The licence texts and the path-by-path licence map | Several licences apply; one place says which covers what |

## Entry points

The maintained brand source is `brand/source/works/`; generated, committed consumer files are in `brand/bundle/works/`.
`scripts/export-brand.mjs` builds and validates the manifest with the vendored shared executor in `tools/brand-bundle/`.
The sponsor adapter reads the bundle's template, stylesheet and behavior; the gallery in `assets/works-gallery.html`
is generated outside the bundle. `design/marks/` retains co-design and the optional historical renderer.

- **Run it:** `npm run dev` for the static site; `npm run dev:worker` for the site behind its Worker.
  [Development](DEVELOPMENT.md) has every command.
- **Start reading here:** `src/pages/index.astro` for the walk, `worker/index.ts` for what happens at the edge,
  `site.config.mjs` for identity, links and legal facts.
- **Tests:** `npm run check` (types, unit and workerd tests, build, output check); `npm run qa` for the browser suite.

## Layout decisions worth keeping

- The contact service stays in `worker/contact/` and `shared/`, independent of the page. It moved here from
  `wolfsblvt.com` unchanged; keeping it separate keeps its tests and guarantees intact and lets another page host it.
- `site.config.mjs` is the single source for identity, destinations and legal facts. Pages, the footer, the identity
  assets and the publication check all read it; duplicating a link elsewhere makes them drift.
- Icons come only from `@wolfsblvt/icons`. There is no local icon folder on purpose.
- Build output goes to `artifacts/`, never into a source folder, so a clean checkout is always a clean source tree.
- Feature code lives with its feature (`src/features/<feature>/`) once it has its own content, client code and styles;
  smaller page behaviour stays in `src/scripts/`.
